# 03: 타깃 = 기기 선택 조건 — Cycle 매트릭스 열이 조건에 맞는 아무 기기로 채워진다

**What to build:** Cycle 을 만들 때 타깃을 이름과 기기 선택 조건(플랫폼, 모델, OS 버전 범위)으로 정의한다. 클레임은 내놓은 idle 기기 중 그 조건에 맞는 기기가 있을 때만 그 타깃의 Run 을 준다. 매트릭스 열은 지금처럼 타깃 이름이고, 셀마다 실제로 돈 기기가 보인다. 데몬은 더 이상 `--targets` 로 맡을 타깃을 선언하지 않아도 된다(조건이 정한다).

**Blocked by:** 02 (클레임 때 기기 lease)

**Status:** ready-for-agent

- [ ] 조건 형식: 플랫폼(필수), 모델(선택, 정확히 일치 또는 목록), OS 버전 범위(선택, 최소·최대). 잘못된 조건은 `POST /cycles` 400. 형식은 계약이므로 protocol 계약 테스트를 먼저 갱신
- [ ] 하위 호환: 문자열 타깃(`android`)은 "그 이름을 맡겠다고 선언한 노드" 규칙으로 계속 동작(데몬 `--targets`). 새 조건 타깃과 섞인 Cycle 도 허용할지 결정하고 명시
- [ ] 클레임 매칭: 조건에 맞는 기기가 여럿이면 고르는 규칙(예: 오래 쉰 기기 먼저)을 정하고 테스트. 맞는 기기가 없으면 Run 은 대기(blocked 아님)
- [ ] Cycle 뷰: 타깃 정의(조건)와 셀·run 행의 기기(마스킹). 같은 타깃의 Run 이 다른 기기에서 대체되면 대체 사슬에 기기도 보인다
- [ ] GLOSSARY 의 "타깃" 정의 갱신 확인, spec 0001 에 조건 형식·매칭 규칙
- [ ] 테스트: Android 13 이상 조건 타깃 + Android 12·13 기기 → 13 기기만 클레임, 모델 지정 타깃, 조건에 맞는 기기 없음 → 대기
