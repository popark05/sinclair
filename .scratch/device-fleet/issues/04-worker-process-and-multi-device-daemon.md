# 04: run 마다 워커 프로세스 + 다기기 데몬 — 한 노드가 꽂힌 기기 수만큼 동시에 돈다

**What to build:** 데몬이 run 을 같은 프로세스가 아니라 run 하나당 자식 워커 프로세스로 실행한다(러너의 테스트 등록이 프로세스 전역이라 한 프로세스에서는 run 이 직렬로만 돈다). 그 위에서 데몬은 lease 받은 기기마다 run 을 동시에 돌린다. 운영자는 노드당 데몬 하나만 띄우면 기기 3대가 각자 다른 Run 을 동시에 처리하는 것을 본다.

**Blocked by:** 02 (클레임 때 기기 lease)

**Status:** ready-for-agent

- [ ] 워커: 데몬이 run 별 자식 프로세스를 띄워 결과(종료 코드·요약)를 받는다. 데몬 종료 신호·lease 상실 취소는 자식에게 전달되어 지금과 같은 의미(현재 테스트까지 마치고 cancelled). 자식이 죽으면 그 run 은 지금의 "에이전트가 죽음" 규칙(버려진 Run)으로 처리된다
- [ ] 스풀: 워커가 쓰고 데몬이 재시작 때 이어 보낸다. 동시 run 들이 서로의 스풀을 건드리지 않는다(기존 pid lock 규칙 확인)
- [ ] 동시성: 기기마다 한 번에 run 하나. 상한 옵션(기본 = 기기 수). heartbeat 는 run 별
- [ ] 설치본(번들)에서도 워커가 뜬다: 자식 실행 경로가 리포 체크아웃·설치 배치 둘 다에서 동작(verify-install 로 확인)
- [ ] 테스트: 가짜 기기 3대 노드 → Run 3개가 겹쳐서 돈다(시작·끝 시각이 겹침), 하나를 SIGKILL 해도 나머지는 끝남, 데몬 SIGTERM → 세 run 모두 현재 테스트까지 마치고 cancelled
