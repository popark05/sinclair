# 01: agent.act 골격과 닫힌 툴 스키마 — 대본 모델로 목표 한 줄이 화면 조작이 된다

**What to build:** 테스트 파일이 `agent.act('아이디 qa 로 로그인해줘')` 처럼 자연어 목표를 주면, 에이전트가 화면을 관찰하고 모델에게 닫힌 툴 집합(탭·입력·스크롤·뒤로·완료 등)으로만 행동을 고르게 해 엔진으로 실행하고, 목표를 이루거나 한도에 닿으면 끝낸다. 이 티켓의 모델은 **대본대로 답하는 가짜 모델**이라 네트워크 없이 결정적으로 돈다. 스텝은 `step.recorded(kind act, modelCalls)` 로 보고된다. 새 에이전트 패키지는 protocol 에만 기대고 러너가 그것을 쓴다(protocol ← agent ← runner).

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 툴은 하나의 action spec 에서 만든다: 각 툴의 이름·인자 스키마·엔진 동작이 한 곳에 있고, 모델에 주는 스키마와 실행기가 같은 원천에서 나온다(어긋나면 계약 테스트가 실패). 닫힌 스키마라 모르는 툴·인자는 실행 전에 거부
- [ ] `StepExecutor` 경계: 에이전트 루프는 "관찰 + 목표 + 지난 턴 → 다음 툴 호출" 을 실행기에 묻는다. 대본 실행기(가짜 모델)가 테스트용 기본 구현
- [ ] 루프 한도: 턴 수·시간 상한(기본값과 이유 주석), 한도에 닿으면 act 실패(사유). 모델이 "완료" 를 고르면 성공
- [ ] 관찰은 엔진 observe 의 secure redaction 을 거친 것만 모델에 간다(기존 redactSecure)
- [ ] 러너 fixture `agent` 와 이벤트: act 하나가 스텝 하나, 안의 툴 실행은 instruction 에 요약, modelCalls 는 실제 묻은 횟수
- [ ] 테스트: FakeEngine 로그인 시나리오에서 대본(아이디 입력 → 비밀번호 입력 → 로그인 탭 → 완료)으로 HOME 에 닿음, 닫힌 스키마 위반 거부, 턴 한도 초과 실패, 스텝 이벤트가 검증기를 통과
